Why AI agents
get worse as the
project grows

Brandon Garate · VibeDrift · github.com/VibeDrift/VibeDrift

The mechanism

It makes reasonable choices
that are not your choices.

Every fresh session starts with no memory of the conventions your codebase already settled on.

  • One handler throws a typed error. The next returns a plain object.
  • Eight services go through the repository layer. The ninth reaches for raw SQL.
  • Everything compiles. Everything passes review.

Why the twentieth session is worse than the second

The agent isn't getting dumber.
Its view of the repo is shrinking.

  • At 500 lines it sees everything. At 80,000 it sees a slice, chosen by what looks like the task, not by what set the convention.
  • Once two ways coexist, the next session sees both and has no reason to prefer either. Every fork is a new place to fork.
  • A linter checks one file against a rulebook. A reviewer checks whether the diff works. Neither checks the codebase against itself.

That gap is what we call drift. It is always relative to a baseline the repo itself established.

The core idea

No finding
without a baseline.

A peer group is a precondition, not a nice-to-have. No baseline, no finding.

The rules we hold ourselves to

Drift, not quality.

  • One measurement. How far a repo has drifted from its own dominant conventions. Not a quality score. Not a debt score.
  • Honesty over confidence. When it isn't sure it hedges or stays silent. Nothing to measure earns an N/A, not a free 20.
  • Never false-bless. It may over-flag. It must never mark an unauthenticated route as authenticated.
  • Consistent does not mean safe. Printed under the security bar, every scan.

The test every change has to pass: does this make us measure drift more accurately, or more confidently?

Where it runs

Before it writes,
not after you review.

An MCP server the agent calls mid-session. It answers from the same baseline the batch scan built, so the in-loop verdict can't contradict the report.

claude mcp add vibedrift \
  -- npx -y @vibedrift/cli mcp

# agent, mid-edit:
validate_change(file, contents)
  → fits: true | false | null

Three states, not two. null means unsure, and unsure never blesses.

Running now · ~20 seconds

What it's doing
while we wait

  • Groups files by directory, because conventions are local.
  • Votes on the dominant pattern in each group.
  • Needs 70% agreement to call it a convention at all.
  • Weights code from this week about twice as heavily as code from three months ago.

Below 70%, it reports nothing. A repo that never agreed with itself has no convention to drift from.
